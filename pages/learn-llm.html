心法 · 一句话总纲CORE INSIGHT · ONE SENTENCE

整台机器里唯一让不同 token 交换信息的地方,只有注意力的 attn @ V。其余全是"逐位置各干各的":Embedding、FFN、LM Head 都是每个 token 独立过同一套变换。

In this whole machine, the only place different tokens exchange information is attention's attn @ V. Everything else is position-wise: Embedding, FFN and LM Head each push every token independently through the same transformation.

SCENE 1 · 分词 TOKENIZATIONTOKENIZATION

文字不直接进模型 · 先切块,再变整数Text never enters the model directly · chop it, then turn it into integers

token → id 只是"查字典":每个 token 在词表里的行号。反过来 id → token 叫 detokenize / decode,生成时用它把数字翻回文字。

token → id is just a dictionary lookup: each token's row number in the vocabulary. The reverse, id → token, is detokenize / decode — used at generation time to turn numbers back into text.

进阶 · 真实模型怎么切:BPE / subwordAdvanced · How real models split: BPE / subword

真实模型用 BPE(字节对编码)反复"合并高频字节对":英文 "playing" → "play" + "ing";中文可能字级或子词级。所以一个词可能拆成多块,多个字符也可能并成一块。玩具版为了好画,直接按词切。

Real models use BPE (byte-pair encoding), repeatedly merging frequent byte pairs: "playing" → "play" + "ing"; Chinese may split at character or subword level. So one word can become several tokens, and several characters can merge into one. The toy version splits by word for easy drawing.

⚠️ 常见误区⚠️ Common traps
❌ "一个字 = 一个 token"。→ ✅ 实际由 BPE 决定:可能一个词拆成多块,也可能多字符并一块。❌ "One character = one token." → ✅ BPE decides: a word may split into several tokens, several characters may merge into one.

SCENE 3 · 位置编码 POSITIONAL ENCODINGPOSITIONAL ENCODING

告诉模型"谁在第几位"Tell the model "who sits where"

注意力本身对顺序无感——打乱 token,结果一样。必须额外注入"位置"。GPT-2 式做法:可学习位置嵌入,和词向量形状相同、逐元素相加。相加后每个向量既含"我是什么词",又含"我在第几位"。

Attention itself is order-blind — shuffle the tokens and the result is identical. Position must be injected. GPT-2 style: a learnable positional embedding, same shape as the word vectors, added element-wise. After the add, each vector carries both "what word I am" and "where I sit".

RoPE never touches the word embeddings and adds no position at the input: it drops pos_emb and instead rotates Q and K inside attention by a position-dependent angle (later positions rotate more), so the Q·K dot product carries "relative position" for free. 为什么必须"先 view 再 transpose"?Why "view first, then transpose"?
view 只能沿现有内存顺序"重新分组"(把连续的 6 劈成 2×3),不能跨维重排;transpose 只能交换两个轴,不能把一个轴劈成两个。所以两步:view 负责"劈开",transpose 负责"换位"。顺序不能反。view can only regroup along the existing memory order (split a contiguous 6 into 2×3), never reorder across dims; transpose can only swap two axes, never split one into two. Hence two steps: view splits, transpose swaps. The order cannot be reversed.
三兄弟 + reshape 速记The three siblings + reshape, at a glance
view       : 重新解释连续内存,不搬数据
transpose : 改 stride 换轴,不搬数据 → 不连续
contiguous: 真复制成新连续内存
reshape   : 能 view 就 view,否则悄悄复制
view       : reinterpret contiguous memory, no data moves
transpose : swap axes via strides, no data moves → non-contiguous
contiguous: real copy into fresh contiguous memory
reshape   : views when it can, silently copies when it can't
⚠️ 常见误区(错题 8)· transpose 后 view 为什么报错?⚠️ Common trap (mistake #8) · why does view fail after transpose?
❌ "维度和 T/d_model 对不上"。→ ✅ 维度完全合法。真因:transpose 后张量不连续,view 拒绝在非连续内存上工作。维度对不对 ≠ 连不连续,两码事。少了 .contiguous() 就报 view size is not compatible with ... stride。❌ "The dims don't match T/d_model." → ✅ The dims are perfectly legal. Real cause: after transpose the tensor is non-contiguous, and view refuses to work on non-contiguous memory. Dim-validity ≠ contiguity — two different things. Skip .contiguous() and you get view size is not compatible with ... stride.
SCENE 6 · 缩放点积注意力SCALED DOT-PRODUCT ATTENTION

唯一跨 token 混合的地方!The only place tokens ever mix!

每个 token(以 Q 的身份)和所有 token(以 K 的身份)算相关度,再按相关度加权搬运 V。全机器只有这里让 token 之间通气。

Each token (as Q) scores its relevance against all tokens (as K), then carries V weighted by those scores. This is the only place in the whole machine where tokens talk.

① scores = Q @ K^T          [4,3]@[3,4] → [4,4]

③ scores.masked_fill(mask==0, -inf)  因果掩码causal mask
④ attn = softmax(scores, dim=-1)  key 维归一!normalized over the key dim!
⑤ out = attn @ V            [4,4]@[4,3] → [4,3]

SCENE 6.5 · RoPE 旋转位置编码专题RoPE DEEP DIVE

位置不是"加"进去,是"转"进去Position isn't added in — it's rotated in

承接 Scene 3 的预告:RoPE 就活在 Scene 6 的内部——在 Q·K 打分之前,先把 Q、K 各自按位置旋转,让注意力分数只依赖两个 token 的相对距离 (n−m),而不是绝对门牌号。

Following the preview in Scene 3: RoPE lives inside Scene 6 — before the Q·K scoring, Q and K are each rotated by position, so the attention score depends only on the relative distance (n−m) between two tokens, not their absolute house numbers.

SCENE 6.6 · KV CACHE 推理加速专题KV CACHE DEEP DIVE

为什么历史不用重算Why history never needs recomputing

痛点(挤牙膏式生成):生成第 k 个词,朴素做法是把已生成的整句重新喂进模型跑一遍完整前向,只为产出 1 个新词——历史那一大坨每步从头再算,98% 是重复劳动。只在推理 / 自回归生成时用,训练不用(训练一次性喂全句、并行算)。动画演示见 Scene 13。

The pain (toothpaste-tube generation): to produce word k, the naive way re-feeds the entire sentence-so-far through a full forward pass just to get 1 new word — the whole history is recomputed every step, 98% wasted work. Used only at inference / autoregressive generation, never in training (training feeds the full sentence once, in parallel). Animated demo in Scene 13.

为什么 BERT(双向)不能缓存Why BERT (bidirectional) can't cache
没有因果掩码,位置 i 会看未来;新 token 一来,x_i 的表示就变 → 缓存的 k_i/v_i 变成过期脏数据,用了会算错(不是"没必要",是"会错")。能缓存是因果掩码换来的红利。Without a causal mask, position i sees the future; a new token changes x_i's representation → cached k_i/v_i become stale dirty data — using them gives wrong answers (not "unnecessary", but "incorrect"). 为什么只缓存 K/V,不缓存 QWhy cache only K/V, never Q
判据是复用,不是"固定 vs 千变万化"。q_i 一生只用一次(它自己那步),用完即弃;k_i/v_i 被之后每一步反复查阅。口诀:存被反复复用的(K/V),别存用一次就扔的(Q)。The criterion is reuse, not "fixed vs ever-changing". q_i is used exactly once in its life (its own step), then discarded; k_i/v_i get consulted by every later step. Mantra: cache what's reused (K/V), never what's used once and tossed (Q).
复杂度 · "KV cache 把 O(n²) 降成 O(n)" —— 对一半错一半COMPLEXITY · "KV cache turns O(n²) into O(n)" — half right, half wrong
✅ 对:每生成一个词(单步)的代价 O(n²) → O(n)
❌ 错:生成整句的注意力点积总量仍是 1+2+…+n = O(n²)✅ Right: the cost per generated word drops O(n²) → O(n)
❌ Wrong: the whole-sentence attention dot-product total is still 1+2+…+n = O(n²)
新 q 和全部历史 key 的点积是省不掉的刚需;真正砍掉的是"把历史整条前向再跑一遍"的浪费(历史的 K/V 投影、FFN、LayerNorm、多头拆合、老 query 的冗余点积)。一句话:单步 O(n²)→O(n),整句 O(n³)→O(n²);砍的是重跑历史前向,不是砍刚需点积。Dotting the new q against every cached key is an irreducible necessity; what actually gets cut is the waste of re-running history's full forward pass (its K/V projections, FFN, LayerNorm, head split/merge, old queries' redundant dots). One line: per step O(n²)→O(n), whole sentence O(n³)→O(n²); the cut is re-running history, not the essential dots.
进阶 · 工程代价:长上下文为什么吃显存(MQA / GQA)Advanced · the engineering cost: why long context eats VRAM (MQA / GQA)

每一层 attention 各有自己的 K/V 仓库,缓存大小 ≈ 2(K和V) × 层数 × n_heads × d_k × 序列长度 × batch,随上下文线性增长且常驻显存——长上下文推理的显存瓶颈。由此催生 MQA / GQA:多个 query 头共享同一组 K/V,把仓库缩小几倍(了解即可)。

Every attention layer keeps its own K/V warehouse; cache size ≈ 2 (K and V) × layers × n_heads × d_k × seq_len × batch — it grows linearly with context and stays resident in VRAM: the memory bottleneck of long-context inference. Hence MQA / GQA: multiple query heads share one K/V set, shrinking the warehouse severalfold (awareness-level).

❌ "Q 不缓存因为 K/V 固定、Q 千变万化"。→ ✅ K/V 也每步在长大;真判据是复用次数。

Key insight: thanks to the causal mask, history tokens' K and V never change when new tokens are appended. So cache every layer's K/V per history token; each new step computes only the new token's Q/K/V and runs attention against "cached K/V + new K/V". From "recompute the whole sequence each step" down to "compute one new token each step" — the engineering core of inference speedup. 一个个吐词,自产自喂。一步错 → 错词回喂 → 掉进训练没见过的状态 → 滚雪球。这就是 exposure bias 曝光偏差(错题 5),缓解:scheduled sampling(训练偶尔喂自产,逐步断奶)。Spits out words one by one, feeding on its own output. One mistake → the wrong word is fed back → the model lands in states never seen in training → snowball. This is exposure bias (mistake #5); mitigation: scheduled sampling (occasionally feed the model's own output during training — gradual weaning).
