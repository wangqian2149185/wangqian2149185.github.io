## 0. 全局设定:一个贯穿始终的玩具例子

整份网页**只用这一个例子**,从头贯穿到尾,读者才能追着同一批数字看它怎么变形。

**例句(输入):** `猫 追 老鼠 。`

**故意调小的配置(方便画图):**

```
B  (batch 批大小)      = 1        只喂一句
T  (seq_len 序列长度)  = 4        四个 token: 猫 / 追 / 老鼠 / 。
vocab (词表大小)       = 12       玩具词表
d_model (模型维度)     = 6        每个 token 的向量长度
n_heads (注意力头数)   = 2        两个头
d_k (每头维度)         = 3        = d_model / n_heads = 6/2
d_ff (FFN 隐层)        = 24       = 4 * d_model
n_layers (层数)        = 2        两个 Transformer Block 叠起来
```

**玩具词表(供可视化查表用):**

```
id:  0=<pad> 1=<bos> 2=. 3=猫 4=追 5=老鼠 6=狗 7=咬 8=人 9=鱼 10=吃 11=<eos>
```

例句分词后的 token id 序列:`[3, 4, 5, 2]`  →  形状 `[T] = [4]`(还没进 batch)。

> **可视化建议(全站通用配色约定):**
> - 每个 token 用一个固定颜色的竖条(猫=橙 / 追=蓝 / 老鼠=绿 / 。=灰),从头贯穿到尾,读者一眼追踪同一个 token。
> - 张量统一画成"方块矩阵",**行 = token(时间/序列维),列 = 特征(d_model 维)**。鼠标悬停显示 `[shape]`。
> - 顶部放一个常驻的 "形状进度条 / shape breadcrumb",实时显示当前张量形状,如 `[1, 4, 6]`。

      │  │  ④ LN1 → 多头自注意力(因果掩码)→ +残差 │

      │  └───────────────────────────────────────┘
      ▼                                          每层进出都是 [4, 6]

> 其余全是"逐位置各干各的":Embedding、FFN、LM Head 都是**每个 token 独立过同一套变换**。

## Scene 1 · 分词 Tokenization(文本 → 整数)

**目的:** 让读者看到"文字不是直接进模型的,先被切成 token,再变成整数 id"。

**输入 → 输出:**
```
"猫追老鼠。"  →  ["猫","追","老鼠","。"]  →  [3, 4, 5, 2]
   字符串            token 列表 (长度4)          id 列表  shape [4]
```

**关键点:**
- 真实模型用 **BPE / subword** 把词切成子词块(如英文 "playing"→"play"+"ing"),中文可能字级或子词级。这里玩具版直接按词切。
- token → id 只是"查字典":每个 token 在词表里的行号。
- 反过来 id → token 叫 **detokenize / decode**,生成时用它把数字翻回文字。

**可视化建议:**
- 动画:一句话"啪"地裂成若干彩色 token 方块,每块下方翻牌出一个整数 id。
- 交互:提供一个输入框让读者自己敲一句话,实时看它被切成 token + id(玩具词表内)。
- 侧注:BPE 的"合并高频字节对"可做成一个可选的进阶小动画(把 l-o-w-e-s-t 逐步合并)。

**常见误区(做成 ⚠️ 提示卡):**
- ❌ "一个字 = 一个 token"。→ 实际由 BPE 决定,可能一个词拆成多块,也可能多字符并一块。

## Scene 2 · 词嵌入 Embedding(整数 → 向量,查表)

**目的:** 每个 token id 去一张大表里取出它专属的 d_model 维向量。

**输入 → 输出:**
```
token id  [3, 4, 5, 2]        shape [T]      = [4]
        │  Embedding 查表 (nn.Embedding(vocab, d_model))
        ▼
词向量矩阵                     shape [T, d_model] = [4, 6]
```

**Embedding 表本身:** 形状 `[vocab, d_model] = [12, 6]`,是**可学习参数**。"查表"= 取出第 3、4、5、2 行。

**具体数字(示意,供画矩阵用):**
```
        d0     d1     d2     d3     d4     d5
猫(3)  0.21  -0.44   0.10   0.87  -0.12   0.33
追(4) -0.05   0.62  -0.31   0.14   0.77  -0.20
老鼠(5) 0.40   0.09   0.55  -0.66   0.02   0.48
。(2) -0.30  -0.11   0.24   0.05  -0.51   0.19
```

**可视化建议:**
- 画一张高高的 `[12, 6]` 表(vocab 行),四条彩色射线从 id [3,4,5,2] 分别"点亮"对应行,抽出来叠成 `[4,6]` 的小矩阵。
- 悬停某一行显示"这是 token X 的语义指纹"。
- 类比卡(贴合读者背景):像给每个**氨基酸残基**查一个 learned embedding(ESM 里就是这么干的),id→向量。

**常见误区:**
- ❌ 以为 embedding 向量是"人手设计的"。→ 是**训练学出来**的参数,初始随机。

## Scene 3 · 位置编码 Positional Encoding(告诉模型"谁在第几位")

**目的:** 注意力本身对顺序无感(打乱 token 结果一样),必须额外注入"位置"。

**做法 A(本 bootcamp 主线 / GPT-2 式):可学习位置嵌入 learnable pos_emb**
```
位置 id   [0, 1, 2, 3]              (torch.arange(T))
        │  pos_emb 查表 (nn.Embedding(max_len, d_model))
        ▼
位置向量                            shape [4, 6]
        │
X = 词向量 + 位置向量  (逐元素相加 element-wise)   shape [4, 6]
```

**关键点:** 词向量和位置向量**形状相同、直接相加**。相加后每个 token 的向量里既含"我是什么词"又含"我在第几位"。

**做法 B(现代 LLaMA/GPT 式,S05 收尾要正式讲):RoPE 旋转位置编码**
> 先埋在这里,细节留给 RoPE 专题 Scene。核心区别一句话:
> - pos_emb 是**在输入端把位置"加"进向量**;
> - RoPE **不动 token 向量、不在输入端加**,而是**在注意力内部按位置把 Q 和 K 各自旋转一个角度**,让 Q·K 的点积自带"相对位置"。
> - 位置注入点从"输入相加" 挪到了 "注意力内旋转"。

**可视化建议:**
- 做法 A:两张 `[4,6]` 矩阵叠加动画(词向量 + 位置向量 → X),用 "+" 号和逐格相加高亮。
- 位置编码本身可以画经典的 sin/cos 条纹热力图(即使主线用 learnable,也放一个 sinusoidal 版热力图当直觉)。
- RoPE 预告:画一个二维向量被"旋转"不同角度的小动画,位置越靠后转得越多。

**常见误区(错题 10):**
- ❌ "RoPE = 包住词嵌入 `RoPE(vocab_emb)`" 或 "替换 pos_emb+vocab_emb 相加"。
- ✅ RoPE 不碰词嵌入、不在输入加位置;它去掉 pos_emb,改在注意力内旋转 Q/K。

## Scene 4 · Q / K / V 投影(把 X 变成"提问/索引/内容"三副面孔)

**目的:** 同一个 X,用三个不同的线性层投影成三个角色。

**输入 → 输出:**
```
X                shape [4, 6]
   │  三个独立线性层
   ├── W_q (6→6) ──► Q  [4, 6]   Query  "我想找什么"(提问方)
   ├── W_k (6→6) ──► K  [4, 6]   Key    "我是什么、可被搜到"(索引)
   └── W_v (6→6) ──► V  [4, 6]   Value  "被选中后我贡献什么内容"
```

**比喻(网页做成三张面具):**
- Q = 一个 token 举手提问:"我(追)最该关注谁?"
- K = 每个 token 挂出的标签牌,供别人匹配。
- V = 每个 token 真正携带、准备被搬运的信息。
- 图书馆比喻:Q=你脑中的问题,K=书脊上的关键词,V=书里的内容。

**可视化建议:**
- 一个 X 矩阵分三路,经过三个不同颜色的权重块,变成 Q/K/V 三个 `[4,6]` 矩阵并排。
- 强调:此时还没有任何 token 之间的交互,纯粹是**逐位置**的线性变换。

## Scene 5 · 拆多头 Split Heads(把 6 维切成 2 头 × 3 维)

**目的:** 让模型在多个"子空间"里并行地各看各的关注模式。**这是 view / transpose / contiguous 的主场。**

**形状变换(以 Q 为例,K/V 同理):**
```
Q            [B, T, d_model]      = [1, 4, 6]
  │  ① view: 把最后一维 6 劈成 (n_heads=2, d_k=3)      —— 只是"重新分组",不搬数据
  ▼
             [B, T, n_heads, d_k] = [1, 4, 2, 3]
  │  ② transpose(1, 2): 把 head 维提到 token 前面     —— 只改读法(stride),不搬数据
  ▼
             [B, n_heads, T, d_k] = [1, 2, 4, 3]
```

**为什么必须"先 view 再 transpose",不能一步到位 `[B,n_heads,T,d_k]`?**
- `view` 只能**沿现有内存顺序重新分组**,能把连续的 6 劈成 2×3,但不能把 head 挪到 T 前面(那是跨维重排)。
- `transpose` 只能**交换两个轴**,不能把一个轴劈成两个。
- 所以要两步:view 负责"劈开",transpose 负责"换位"。顺序不能反(先换再劈,劈的结果就错位了)。

**view / transpose / contiguous 三兄弟(核心概念卡):**
```
view       : 重新解释同一段连续内存,不搬数据;只能沿内存顺序重新分组;结果仍连续。
transpose  : 交换两个轴,靠改 stride(步长)实现,不搬数据;但逻辑遍历顺序变了 → 结果"不连续"。
contiguous : 定义 = "按行优先(row-major)的逻辑遍历顺序 == 物理内存顺序"。
             .contiguous() = 真的把数据按新顺序复制到一块新内存(已连续则近乎空操作)。
reshape    : "能 view 就 view,否则自动 contiguous 再 view"(更宽容,但可能悄悄复制)。
```

**为什么 transpose 后 view 会报错?(错题 8)**
- 合并多头时 `out.transpose(1,2).view(B,T,d_model)`,若少了 `.contiguous()` 会报错。
- ❌ 误以为报错是"view 的维度和 T/d_model 对不上"。
- ✅ 维度/元素数完全合法,和报错无关。真因:**transpose 后张量不连续,而 view 拒绝在非连续内存上工作**(报 `view size is not compatible with ... stride`)。**维度对不对 ≠ 连不连续,两码事。**

**可视化建议(读者点名要过的图,重点做好):**
- 画一段**扁平内存条**(格子 a,b,c,d,e,f...),上方分别叠加 view 后的分组框、transpose 后的读取箭头。
- 关键动画:view 时"分组框"重画但内存条纹丝不动;transpose 时"读取箭头的走向"改变(变成跳着读),内存条依旧不动 → 直观看出"为什么 transpose 后不连续"。
- contiguous 时演示"按新箭头顺序把格子搬进一条新内存条"。

## Scene 6 · 缩放点积注意力 Scaled Dot-Product Attention(唯一跨 token 混合的地方!)

**目的:** 每个 token(以 Q 的身份)去和所有 token(以 K 的身份)算相关度,再按相关度加权搬运 V。**全机器只有这里让 token 之间通气。**

**四步公式(每头独立进行,shape 以单头 `[T, d_k]=[4,3]` 记):**
```
① 打分   scores = Q @ K^T                 [4,3]@[3,4] → [4, 4]   (每个 query 对每个 key 的相似度)
② 缩放   scores = scores / sqrt(d_k)       除以 sqrt(3),防止点积过大把 softmax 推到饱和
③ 遮挡   scores = scores.masked_fill(mask==0, -inf)   (仅因果/decoder 需要,见下)
④ 归一   attn = softmax(scores, dim=-1)    [4, 4]   在 key 维(最后一维)归一化成概率
⑤ 加权   out  = attn @ V                   [4,4]@[4,3] → [4, 3]   按注意力权重把 V 搬过来求和
```

**因果掩码 Causal Mask(GPT 必备):**
```
构造: mask = torch.tril(torch.ones(T, T))     下三角为 1,上三角为 0
含义: 位置 i 只能看 0..i(含自己),看不到未来 i+1..(右上角被 -inf 挡死)

scores 矩阵(行=query 位, 列=key 位), ✓可见 ✗被 -inf 挡:
          key: 猫    追    老鼠   。
   query 猫 [  ✓    ✗    ✗    ✗ ]   猫只能看自己
   query 追 [  ✓    ✓    ✗    ✗ ]   追能看 猫+自己
 query 老鼠 [  ✓    ✓    ✓    ✗ ]   老鼠能看 猫追+自己
   query 。 [  ✓    ✓    ✓    ✓ ]   。能看全句
```

**掩码机制细节(已掌握,可做成小推导动画):**
```
被挡的位置填 -inf  →  e^(-inf) = 0  →  softmax 后权重=0(等于不存在)
分母只累加可见位置的 e^score,所以每行权重仍然规规矩矩加起来 = 1。
```

**关键澄清(错题 9 + softmax 维度,做成醒目卡片):**
- softmax 在 **key(token)维** 归一:对每个 query,在"所有可见 key"上算一个概率分布。**和 d_model 无关、和 vocab 无关。**
- 这是全网络的**第一个 softmax**;末尾 LM Head 之后还有**第二个 softmax(在 vocab 维)**。两个别混。

**可视化建议(全站高潮面板,重点投入):**
- 核心画一张 `[4,4]` 的注意力热力图,行=query token,列=key token,格子亮度=权重。
- 因果掩码:右上三角格子打叉/变灰,读者能看到 softmax 后每行只在左下有亮块、每行和为 1。
- 交互:滑杆改 sqrt(d_k) 缩放,看热力图"变尖锐/变平缓"(温度直觉的前奏)。
- 动画 ⑤:选中一行(如"追"),演示它按权重把各 token 的 V 向量加权求和,汇成"追"的新向量。

**常见误区(错题 9):**
- ❌ softmax 是"给 d_model 每一维算概率"。→ ✅ 在 key/token 维。
- ❌ "因果掩码把前文 mask 掉"。→ ✅ 挡的是**未来/右边**,前文始终可见。

## Scene 7 · 合多头 + 输出投影 W_o(把各头的结论汇总)

**目的:** 各头各算完 `[B,n_heads,T,d_k]`,拼回 `[B,T,d_model]`,再用 W_o 把"多头的结论"融合。

**形状变换(Scene 5 的逆操作):**
```
每头输出   [B, n_heads, T, d_k] = [1, 2, 4, 3]
  │  ① transpose(1, 2): head 换回 token 后面 → [1, 4, 2, 3]   (改读法,变不连续)
  │  ② contiguous():    按新顺序复制成连续内存                 (为下一步 view 铺路)
  │  ③ view(B, T, d_model): 把 (2,3) 两头合并回 6            [1, 4, 6]
  ▼
合并结果   [1, 4, 6]
  │  ④ W_o (6→6) 线性投影
  ▼
注意力子层最终输出   [1, 4, 6]
```

**W_o 到底混合什么?(错题 9 关键澄清)**
- W_o 形状 `[d_model→d_model]`。它**混合不同 head**(拆头后各头互不通气,W_o 让它们交融)+ 投影回 d_model。
- ❌ 误:"W_o 让 token 之间交换信息"。→ ✅ 跨 token 的活儿注意力早干完了;**W_o 混的是 head,不跨 token。**

**一句话总账(做成对照表面板):**
```
attn @ V      →  混 token(唯一)
W_o           →  混 head
FFN           →  逐位置(不跨 token,见 Scene 9)
LM Head       →  逐位置(不跨 token)
```

**可视化建议:**
- 复用 Scene 5 的内存条动画倒放,强调"合"是"拆"的逆过程,且必须 contiguous 才能 view。
- 画 2 个头的输出被 W_o "搅拌融合"成一个的动画。

## Scene 8 · 残差 + LayerNorm:Transformer Block 的骨架(Pre-LN)

**目的:** 把注意力和 FFN 两个子层,用"先归一化→过子层→加残差"的固定套路串起来。

**Pre-LN Block 结构(本 bootcamp 主线,GPT-2/现代式):**
```
h   = x + Attn( LN1(x) )      注意力子层:先 LN 再进注意力,输出加回原始 x(残差)
out = h + FFN( LN2(h) )       FFN 子层:先 LN 再进 FFN,输出加回 h(残差)

进出形状全程 [B,T,d_model]=[1,4,6],每层不变。
```

**两个铁律(错题 6,重点做成默写检查):**
1. **第二个子层归一化/加工的是 h,不是 x!** `out = h + FFN(LN2(h))`,别写成 `FFN(LN2(x))`。
   每个子层串行,吃**上一个子层的最新输出**。口诀:LN → 子层 → 加残差,一路往下踩。
2. 残差 `x + ...`:给梯度一条高速公路,让深层网络训得动;也让子层只需学"增量修正"。

**LayerNorm 干嘛:** 对每个 token 的向量(在 d_model 维内)做标准化(减均值除标准差,再缩放平移),稳定数值、加速训练。**逐 token 独立,不跨 token。**

**Pre-LN vs Post-LN(了解即可,可做成一个切换对比):**
```
Pre-LN : h = x + Attn(LN(x))     LN 在子层"之前"。现代主流,训练更稳。
Post-LN: h = LN(x + Attn(x))     LN 在残差"之后"。原版 Transformer 论文,深层难训。
```

**可视化建议:**
- 画一个 Block 的"管道图":x 分两路,一路走 LN→Attn,一路直连(残差),在加号汇合成 h;h 再同样走 FFN 一遍。
- 高亮"第二子层吃的是 h 不是 x"——用颜色区分 x(浅)和 h(深),让读者看到 FFN 那一路接的是深色 h。

**常见误区(错题 6):**
- ❌ `out = h + FFN(LN(x))`(第二子层回头拿老 x)。→ ✅ 拿最新的 h。

## Scene 9 · 前馈网络 FFN(逐位置的"深加工车间")

**目的:** 每个 token 各自过一个两层 MLP,升维→非线性→降维,做通道内的特征加工。

**形状变换:**
```
输入  [B,T,d_model] = [1,4,6]
  │  Linear1 (6→24)         升维,给非线性更大施展空间
  ▼  [1,4,24]
  │  GELU (激活,非线性)     现代常用 GELU;变体 SwiGLU(了解即可)
  ▼  [1,4,24]
  │  Linear2 (24→6)         降回 d_model
  ▼
输出  [1,4,6]
```

**最关键的一句(错题 7 + 错题 9,做成醒目卡):**
- FFN 是 **逐位置 position-wise**:**每个 token 独立**过**同一套** MLP,token 之间**完全不交流**。
- ❌ 误:"FFN 汇合各 token 的信息"。→ ✅ 汇合 token 是注意力的活;FFN 只在**每个 token 内部**加工特征。
- ❌ 误:"把向量兑成 vocab 分数是 FFN 干的"。→ ✅ FFN 进出都是 d_model,**不碰 vocab**;兑 vocab 是末尾 LM Head 的活。

**口诀:** FFN 在楼里进出同宽(d_model→d_ff→d_model),LM Head 在大门口把 d_model 兑成 vocab。

**可视化建议:**
- 画 4 个 token 各自排队,依次独立过**同一个** MLP 盒子(强调"同一套权重、各过各的"),盒子内部演示 6→24→6 的胖-瘦变化。
- 对比动画:注意力那一屏 token 之间有连线,FFN 这一屏 token 之间**没有任何连线**——直观区分"跨 token vs 逐位置"。

## Scene 10 · 堆叠 N 层 Block Stacking

**目的:** 把 Scene 4~9 的一整个 Block,叠 N 层(玩具里 N=2),每层进出都是 `[1,4,6]`。

```
X [1,4,6] → Block-1 → [1,4,6] → Block-2 → [1,4,6] → ... → 顶层输出 [1,4,6]
```

**直觉:** 浅层学局部/语法,深层学长程/语义(类比 CNN 越深越抽象;类比蛋白模型越深越接近"折叠/功能"级表示)。每层都能让每个 token 再"看一遍全句"并更新自己。

**可视化建议:**
- 竖着叠 N 个一样的 Block 卡片,数据流一条竖线穿下来,形状标签始终 `[1,4,6]` 不变——强调"层不改形状,只改内容"。
- 可选:滑杆调 N,看层数变化。

## Scene 11 · 收尾 LayerNorm + LM Head(向量 → 词表分数)

**目的:** 顶层输出先做最后一次 LayerNorm,再用 LM Head 把每个 token 的 d_model 向量投影成"词表上每个词的分数"。

**形状变换:**
```
顶层输出  [1,4,6]
  │  ln_f (末尾 LayerNorm)
  ▼  [1,4,6]
  │  LM Head:Linear(d_model → vocab) = Linear(6 → 12)
  ▼
logits   [B, T, vocab] = [1, 4, 12]
```

**含义:** `logits[0, i]` 是长度 12 的向量 = "站在第 i 个 token 的位置上,预测下一个词时,词表里每个词的原始分数"。

**权重绑定 weight tying(可选进阶卡):** 很多模型让 LM Head 和 Embedding **共享同一张 `[vocab,d_model]` 表**(一个查表进、一个转置出),省参数、常涨点。

**可视化建议:**
- 画 `[4,6]` 经 LM Head 变成 `[4,12]`,每行从 6 格变 12 格,用玩具词表把 12 列标上词。
- 高亮最后一行(位置"。"):它的 12 个分数就是"下一个词该是谁"的依据。

**常见误区(错题 7):**
- ❌ 以为"向量→vocab 分数"是 FFN 干的。→ ✅ 是最末尾 LM Head 干的,FFN 只在层内 d_model→d_model。

## Scene 12 · 输出 softmax + 采样(分数 → 概率 → 一个词)

**目的:** 把 logits 变成概率,再挑一个词。**这是全网络第二个 softmax(在 vocab 维)。**

**流程(生成时只关心最后一个位置):**
```
取最后位置  logits[0, -1]          shape [vocab]=[12]   ("。"之后该接什么)
  │  softmax(., dim=-1)  ← 第二个 softmax,在 vocab 维!
  ▼
概率分布  probs                     shape [12], 和为 1
  │  采样策略挑一个
  ▼
下一个 token id
```

**三种采样(做成可交互滑杆面板):**
```
greedy 贪心      : 直接取概率最大的 id。稳、但死板重复。
temperature 温度 : probs = softmax(logits / T)。T<1 更保守尖锐,T>1 更浪更平。T=胆量。
top-k / top-p    : 只在前 k 个 / 累积概率 p 的候选里采样,砍掉长尾胡话。
```

**两个 softmax 别搞混(呼应错题 9,做成对照卡):**
```
第一个 softmax:注意力里,在 key/token 维 → 决定"看谁"
第二个 softmax:LM Head 后,在 vocab 维    → 决定"说哪个词"
```

**可视化建议:**
- 画 `[12]` 概率条形图(玩具词表标签),温度滑杆实时改变分布的"尖/平"。
- 三种采样并排:greedy 永远点最高柱;temperature 掷骰子;top-k 先灰掉长尾再掷。

## Scene 13 · 自回归生成 Auto-regressive Loop(+ KV cache 预告)

**目的:** 把 Scene 1~12 串成一个循环:每生成一个词,拼回输入,再跑一遍,直到出 `<eos>`。

```
输入 [3,4,5,2] → 模型 → 采样得 id=10(吃?) → 拼成 [3,4,5,2,10]
                                                     │
                            → 模型(更长序列)→ 采样下一个 → 拼回 → ...
直到采样出 <eos>(id=11) 停止。
```

**朴素做法的浪费:** 每加一个词,就把**整条越来越长的序列**从头重算一遍,历史 token 的 K/V 被反复重算。

**KV cache(S05 收尾要正式讲,先埋钩子):**
> 关键洞察:因为有**因果掩码**,历史 token 的 K、V **不会因为末尾新增而改变**。
> 所以把每层每个历史 token 的 K/V **缓存**起来,新一步只算**新 token 那一个**的 Q/K/V,拿新 Q 去和"缓存的 K/V + 新 K/V"做注意力。
> 从"每步重算全序列"降到"每步只算一个新 token",这是推理提速的工程核心。

**可视化建议:**
- 循环动画:序列末尾一个个长出新彩色方块,每次高亮"这一步模型看的窗口"。
- KV cache 对比:朴素版每步整行重算(全亮),cache 版只有最后一格新算(其余灰色=复用),直观看出省了多少。

## Scene 14 · 三范式对比 BERT / GPT / T5(掩码决定命运)

**目的:** 同一套 Transformer 积木,靠**掩码**和**几半**拼出三种模型。

```
             用几半?              掩码?                干什么         看的方向
BERT   Encoder-only(一半)   无因果掩码(双向)      理解/填空       ←→ 两边都看
GPT    Decoder-only(一半)   因果掩码(单向)        生成/续写       ← 只看左边(过去)
T5     Encoder-Decoder(两半) 编码器双向+解码器因果   seq2seq 翻译    编码双向, 解码看左+查编码器
```

**最容易错的一条(错题 1,已复发 2 次,重点做成互动判断题):**
- ❌ 用"几半/前半后半"区分 BERT 和 GPT。
- ✅ BERT 和 GPT **都是一半**(Encoder-only / Decoder-only),区别在**掩码**(双向 vs 因果)。**两半的只有 T5。**
- 口诀:**掩码决定方向,用几半决定形态。**

**T5 三要素(错题 3):** Encoder-Decoder,唯一"两半",做 seq2seq。左半 Encoder 双向无掩码读懂源;右半 Decoder 因果掩码 + cross-attention 查阅左半、逐词生成。

**Cross-Attention 补充(错题 2):**
```
Decoder 每层 3 个子层:① masked self-attn(戴因果掩码) ② cross-attn(查编码器) ③ FFN
相对 Encoder 真正新增的是中间的 cross-attn。
cross-attn 里:Q 来自解码器(提问方),K/V 来自编码器输出(被查阅方)。
注意力矩阵 A 形状 [tgt_len, src_len] 是长方形——因为两个序列长度不同,不是因为 d_model 不同!
(d_model 必须相同才能算点积。)
```

**可视化建议:**
- 三个模型并排,用"掩码热力图"直观对比:BERT 全亮(双向)、GPT 下三角(因果)、T5 左半全亮+右半下三角+中间一根"cross"连线。
- 互动判断题:给一句"BERT 是前半、GPT 是后半"让读者判对错,点开揭晓 = 错题 1。

## Scene 15 · 训练视角 Training(为什么能一次并行算全句 loss)

**目的:** 前面都是"推理时怎么算";这一屏讲"训练时怎么学",把采样/掩码/loss 串起来。

**Teacher forcing 教师强制:** 训练时喂**真值前缀**(不用等模型自己产的词),配合因果掩码,**一次前向就能并行算出全句每个位置的 loss**。

**为什么能并行?(错题 4,重点澄清)**
- ❌ 误:"因为各位置相互独立、各算各的"。(位置 i 的注意力**要看** 0..i-1,并不独立!)
- ✅ 是两件事叠加:
  1. 喂**真值**前缀 → 所有输入开局全已知,不用等位置 i 的输出;
  2. **因果掩码** → 每个位置只看左边,不会偷看它要预测的答案。

**训练五步心脏(lab-08,顺序固定,做成可拖拽排序题):**
```
zero_grad 擦账 → forward 作答 → loss 打分 → backward 倒推责任(算梯度) → step 照账改人
```
- `backward` 只**算账**(填好每个参数的 `.grad`),`step` 才**照账改人**(更新参数)。
- 次序反了(step 在 backward 前)→ 照空账改,参数永不更新,loss 死平不降。
- 每轮 `zero_grad` 因为梯度默认**累加**,不擦会串味。

**Exposure bias 曝光偏差(错题 5):**
- 训练只见**真值前缀**,推理却要接**自产**词;一步错→错词回喂→掉进训练没见过的状态→滚雪球。
- 根源 = 训练/推理"被暴露的前缀"不一致。缓解:scheduled sampling(训练偶尔喂自产,逐步断奶)。
- 开车类比:训练有人扶方向盘,上路没人扶。

**Loss:** 交叉熵 cross-entropy,比较"模型预测的 vocab 分布"和"真实下一个词"。理想最优 ≈ 模型把真实词的概率顶到最大。

**可视化建议:**
- 并排画"训练"(teacher forcing:整句一次进,因果掩码,每个位置同时算 loss)vs "推理"(自回归:一个个吐,自产自喂)。
- 五步循环做成一个可拖拽排序的小游戏,拖错顺序就演示"loss 一条直线不降"。
- exposure bias 做成"雪球"动画:训练轨道平坦,推理轨道一步偏 → 越滚越偏。

## 附录 B · "谁跨 token / 谁逐位置" 总账(错题 9 核心,建议做成高亮对照面板)

```
操作            跨 token 吗?      它到底混合什么
Embedding       否(逐位置)       id → 向量,各查各的
位置编码相加    否(逐位置)       给每个位置加自己的位置向量
Q/K/V 投影      否(逐位置)       线性变换,每 token 独立
attn @ V        ★是(唯一)★      按注意力权重跨 token 搬运信息
W_o             否               混不同 head(不是 token)
FFN             否(逐位置)       每 token 独立过同一 MLP
LayerNorm       否(逐位置)       每 token 在 d_model 维内标准化
LM Head         否(逐位置)       d_model → vocab,每 token 独立
```
**一句话:attention 混 token,W_o 混 head,其余全逐位置。**

## 附录 D · 错题本(可做成网页末尾"闯关自测"题库)

> 每条都能做成一道互动题(判断/选择/填空),读者答错弹出正解。这些是学习者**真实踩过的坑**,优先级最高。

1. **几半 vs 掩码**(复发 2 次):BERT/GPT 都是"一半",区别在掩码;两半的只有 T5。
2. **Cross-attn 长方形**:A=[tgt_len,src_len] 长方形因**序列长度不同**,不是 d_model 不同(d_model 必须相同)。
3. **T5 三要素**:Encoder-Decoder / 唯一两半 / seq2seq;左双向读源,右因果+cross-attn 生成。
4. **并行算 loss 的原因**:不是"位置独立",是"喂真值前缀 + 因果掩码"两件事叠加。
5. **Exposure bias**:训练喂真值、推理喂自产,不一致 → 滚雪球;缓解 scheduled sampling。
6. **第二子层归一化的是 h 不是 x**:`out = h + FFN(LN(h))`,别写成 `FFN(LN(x))`。
7. **FFN ≠ LM Head**:FFN 层内 d_model→d_model 不碰 vocab;兑 vocab 是末尾 LM Head。
8. **view 报错真因**:transpose 后不连续,view 拒绝在非连续内存工作;不是维度对不上。reshape 更宽容。
9. **谁跨 token**:只有 attn@V 跨 token;W_o 混 head;FFN/LM Head/LN 逐位置。attention softmax 在 key 维。
10. **RoPE 注入方式**:不碰词嵌入、不在输入加位置;去掉 pos_emb,在注意力内按位置旋转 Q/K。
